# Security Policy

Decuff takes the security of our software seriously. Thank you for helping keep
Decuff and its users safe.

## Reporting a vulnerability

**Please do not open a public issue for security vulnerabilities.**

Report privately through either of these channels:

1. **GitHub private vulnerability reporting** — on the affected repository, open the
   **Security** tab → **Report a vulnerability**.
2. **Email** — <security@decuff.ai>. Encrypt sensitive details if possible.

Please include:

- The affected project, version, and commit (if known).
- A description of the issue and its impact.
- Steps to reproduce, proof-of-concept, or a minimal test case.
- Any suggested remediation.

## What to expect

- **Acknowledgement** within 3 business days.
- A triage assessment and severity rating, and a coordinated timeline for a fix.
- Credit for the reporter on disclosure, unless you prefer to remain anonymous.

## Scope

This policy covers the source code in repositories under the `decuff`
organization. Several Decuff projects are offensive-security tools intended for
**authorized** testing only; reports concerning unauthorized use of these tools
against third parties should go to the relevant provider or authorities, not here.

## Safe harbor

We will not pursue or support legal action against researchers who act in good
faith, follow this policy, avoid privacy violations and service disruption, and
give us a reasonable time to remediate before any disclosure.
